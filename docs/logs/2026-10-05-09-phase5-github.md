# 09 — Phase 5 (part 2): GitHub pull requests + Actions

**Date:** 2026-10-05
**Task:** Turn validated fixes into GitHub pull requests, use GitHub Actions as an additional CI gate, and deploy through GitHub without creating untested merge commits.

## What changed
- `integrations/github.py`: REST client (PRs, Actions runs), authenticated `git push` (token in an HTTP header for one command), repo-name normalisation (`owner/name`, `.git`, URLs), token redaction.
- `integrations/github_flow.py`: open PR after validation, refresh CI/merged state, CI gate, push production branch.
- Models `ServiceGitHub`, `PullRequest`; `github_repo` on service registration (default `AION_GITHUB_REPO`).
- Orchestrator opens the PR on `awaiting_approval`; approve endpoint and deployer preflight enforce the CI gate; deployer pushes GitHub `main` (non-force) before the local fast-forward; rollback pushes the revert.
- Dashboard: PR link, Actions status and run links in the approval panel; approve disabled until CI passes.
- Demo: GitHub Actions workflow in the service (`.github/workflows/ci.yml`); `run_demo.py --fresh` mirrors the history to GitHub (`--no-github`).

## Tests
83 passing. `test_github.py` uses a local bare repo as GitHub's git server and an `httpx.MockTransport` as the REST API: PR opened with the right base/body and the branch really pushed; approval 409 while Actions pending; approve + deploy after success; GitHub `main` == validated commit; PR merged; rollback pushes the revert; failed CI blocks approval; tokens never appear in error messages. Tests force-disable the real token from `.env`.

**Live (real GitHub, `aditya-bheke/aion-demo-orders-service`):** demo history pushed (Actions ran on `main`); incident → AION opened **PR #1**; approval refused while CI state `none`; GitHub Actions `pull_request` run completed **success** within ~17 s of polling; approve → deploy → GitHub `main` == the validated commit and GitHub reports **PR #1 merged**; production fixed.

## Problems encountered
1. `AION_GITHUB_REPO` was entered as `owner/name.git` → GitHub API 404. → normalise all common forms instead of asking the user to edit.
2. Fine-grained tokens don't offer the *Checks* permission → read CI from the Actions workflow-runs API (needs only *Actions: read*).
3. After the deploy, AION still showed the PR as open: GitHub detects the fast-forward merge asynchronously and AION had stopped refreshing once CI succeeded. → keep refreshing an open PR while the incident is resolved/rolled back until GitHub reports it merged.
4. Safety: `backend/.env` now holds a real token, so the test fixture blanks `github_token`/`github_repo` to guarantee tests never touch the real repository.

## Status
Phase 5 complete.
